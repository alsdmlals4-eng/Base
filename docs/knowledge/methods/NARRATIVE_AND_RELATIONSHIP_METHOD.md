# 서사·대화·관계 설계 방법

- 상태: 공용 방법
- 목적: 장면·대사·선택·관계를 설정 설명과 분량 채우기가 아니라 사용자 행동과 이후 기억에 연결한다.
- 외부 Source 발견: `docs/knowledge/game-development/PERIODIC_EXTERNAL_SOURCE_WATCHLIST.md`의 `FICTION_AND_INTERACTIVE_NARRATIVE`

외부 소설·게임 Writing 자료는 프로젝트 정본보다 높은 권한을 갖지 않는다. 선형 소설 craft와 interactive narrative는 공통 원리를 공유하되 매체의 입력·상태·검증 경계가 다르므로 그대로 복제하지 않는다.

## 1. 장면의 최소 단위

한 장면은 다음 질문에 답해야 한다.

1. 왜 지금 필요한가?
2. 사용자가 무엇을 새로 보거나 선택하는가?
3. 장면 전후에 무엇이 달라지는가?
4. 어떤 인물·세계·규칙을 행동으로 보여주는가?
5. 다음 장면과 무엇으로 연결되는가?

권장 구조:

```text
상황과 변화
→ 인물의 행동·대화
→ 사용자 선택·해석
→ 즉시 반응
→ 상태·기억·기록
→ 다음 질문 또는 여운
```

한 장면에 여러 핵심 정보와 감정 전환을 동시에 넣지 않는다.

## 2. 대화의 세 모드

### 기능 대화

- 현재 행동, 위험, 비교 기준을 전달한다.
- 짧고 직접적이다.
- 미확인 사실을 단정하지 않는다.
- 현재 선택을 대신하지 않는다.
- 최초 상세와 재방문 축약을 분리한다.

### 관계 대화

- 인물 간 거리·가치관·기억 변화를 보여준다.
- 말투, 침묵, 물건, 시선, 행동 순서를 사용한다.
- 선택의 차이는 다음 반응과 정보 공유에 남긴다.
- 성능 보상보다 장면과 태도 변화가 우선한다.

### 세계관 대화

- 조직·문화·역사·규칙을 생활과 갈등 속에서 보여준다.
- 백과사전식 설명을 피한다.
- 두 인물이 같은 사실을 다르게 해석하게 한다.
- 장면 목적과 무관한 설정은 기록 문서나 별도 콘텐츠로 보낸다.

한 장면에서 한 모드를 중심으로 두고 다른 모드는 보조한다.

## 3. 상황지시문

감정을 평가하기보다 관측 가능한 차이를 제시한다.

```text
공간·소리·빛·사물의 변화
→ 인물·장비의 구체적 반응
→ 아직 확인되지 않은 요소
→ 사용자가 고를 수 있는 행동 여지
```

나쁜 예:

> 방은 매우 무섭고 불길했다.

좋은 예:

> 꺼져 있던 복도등이 문 안쪽부터 한 칸씩 켜졌다. 마지막 전등은 켜지지 않았지만, 그 아래의 그림자는 먼저 움직였다.

## 4. 캐릭터 목소리 카드

캐릭터마다 다음을 기록한다.

- 핵심 욕망.
- 두려움과 회피 행동.
- 책임을 느끼는 대상.
- 판단 기준.
- 말의 길이와 속도.
- 자주 쓰는 문장 구조.
- 감정을 숨기는 방식.
- 갈등 시 바뀌는 말투.
- 친밀해졌을 때만 보이는 행동.
- 절대 하지 않을 말과 행동.

목소리는 어휘 목록보다 **어떤 상황에서 무엇을 먼저 보는가**로 구분한다.

## 5. 설명보다 행동

설정을 직접 설명해야 할 때도 행동과 선택을 먼저 둔다.

```text
규정 위반 행동
→ 다른 인물의 제지
→ 책임 기준 충돌
→ 필요한 규칙 한 문장
```

세계관 정보는 다음 중 하나와 연결될 때 장면에 넣는다.

- 현재 선택의 이유.
- 인물 갈등.
- 다음 사건의 준비.
- 사용자의 새로운 질문.
- 기록·도감·메뉴의 해금.

## 6. 선택지 설계

선택지는 정답 문장과 오답 문장을 감추는 장치가 아니다. 서로 다른 태도·위험·정보·비용을 가져야 한다.

선택지 유형:

- 행동 방식.
- 정보 우선순위.
- 사람과 절차의 우선순위.
- 의심 유지 또는 신뢰.
- 책임 수용 또는 분담.
- 즉시 해결 또는 기록 보존.

좋은 선택지는 선택 직후 행동의 방향을 예측할 수 있다.

## 7. 관계 설계

### 숫자와 경험 분리

내부 계산이 필요하더라도 사용자는 다음으로 관계 변화를 느낀다.

- 말투와 호칭.
- 먼저 말하거나 기다리는 순서.
- 공유하는 정보의 범위.
- 도움 요청과 거절 방식.
- 장면의 거리와 시선.
- 후속 이벤트 해금.
- 기록 문장의 변화.

관계는 성능 보너스보다 인물 이해와 장면 차이를 우선한다.

### 태그 예시

- 신뢰.
- 경계.
- 부채.
- 경쟁.
- 공감.
- 보호.
- 균열.

프로젝트의 핵심 관계 질문에 맞게 선택한다.

### 선택 기억

```text
선택 ID
→ 대상 인물
→ 기억할 태도
→ 발동 가능한 후속 반응
→ 충돌 시 우선순위
→ 소비 또는 유지 여부
```

같은 선택을 반복해 관계 변화와 보상을 중복 획득하지 않게 한다.

## 8. 분기 예산

| 분기 수준 | 변화 | 사용 조건 |
|---|---|---|
| 반응 분기 | 한두 문장·표정·행동 차이 | 대부분의 태도 선택 |
| 장면 분기 | 짧은 추가 장면·정보 공유 | 기억할 가치가 있는 관계 선택 |
| 체인 분기 | 다음 에피소드의 진입·순서 변화 | 핵심 관계 축 |
| 결말 분기 | 장기 결과와 엔딩 변화 | 프로젝트 핵심 약속일 때만 |

많은 작은 반응이 적은 큰 분기보다 ‘선택을 기억한다’는 감각을 줄 수 있다.

## 9. 연속 이벤트

```text
갈등 또는 질문 제시
→ 서로의 방식이 실제 문제를 만남
→ 선택의 비용이나 약점이 드러남
→ 상대 방식을 일부 이해함
→ 새로운 공동 행동 또는 남은 균열
```

같은 갈등을 말만 바꿔 반복하지 않는다.

## 10. 실패와 후일담

후속 장면은 처벌 설명보다 의미 정리를 담당한다.

- 무엇을 잘못 보았는가.
- 누가 어떤 비용을 감당했는가.
- 다음에 무엇을 다르게 할 것인가.
- 관계에 어떤 흔적이 남았는가.
- 기록에 무엇을 남기거나 숨길 것인가.

후일담은 정답을 다시 읽는 장면이 아니라 책임과 기억의 해석을 보여준다.

## 11. 데이터 경계

- 대사 본문은 결과를 새로 계산하지 않는다.
- 선택 결과는 한 곳에서 정의한다.
- 관계 상태와 장면 연출 상태를 분리한다.
- 표정·컷인 파일 경로를 대사 문장에 직접 하드코딩하지 않는다.
- 기록·도감은 이미 발생한 사실을 요약하며 새 필수 사실을 만들지 않는다.
- 자산 부재와 연출 비활성 상태에서도 장면이 진행돼야 한다.

## 12. 작성 절차

1. 장면의 역할과 새 정보 하나를 정한다.
2. 등장인물별 현재 욕망과 판단 기준을 적는다.
3. 대화 없이 행동만으로 장면 흐름을 작성한다.
4. 필요한 대사만 추가한다.
5. 사용자 선택과 즉시 반응을 넣는다.
6. 상태·기억·기록 변화를 정의한다.
7. 다음 장면과의 연결을 적는다.
8. 말투·정보 누설·분량·반복을 검수한다.

## 13. 사례 — 수치를 말하지 않고 같은 사실을 더 구체적으로 말하기

상대의 위험도·성장 상태·전법처럼 내부에는 정확한 값이 있지만, 기본 화면과 대사에서 숫자표를 직접 보여주면 인물이 개발용 태그처럼 보일 수 있다. 반대로 분위기만 있는 문구를 쓰면 사용자는 선택 근거를 얻지 못한다.

해결은 같은 내부 의미 키에 대해 정보 단계별 문장 역할을 정하는 것이다.

```text
내부 의미 키
→ 최초 정보: 방향과 위험 범주만 암시
→ 반복 정보: 같은 어휘 계열로 의미를 학습
→ 상세·정탐 정보: 같은 사실을 더 구체적으로 표현
→ 결과 장면: 실제 행동으로 문구의 의미를 입증
```

예시 형식:

- 최초: “한 계통만을 오래 벼렸다는 소문이 있다.”
- 반복: “다른 기술보다 같은 초식을 거듭 다듬었다고 한다.”
- 상세: “상위 기술의 문턱에 가까우며 보조 계통의 흔적은 적다.”

작성 규칙:

- 문구는 선택 근거를 제공하지만 정답 행동을 대신 말하지 않는다.
- 높은 정보 단계는 이전 문장을 뒤집지 않고 구체성만 높인다.
- 같은 의미에 같은 어휘 계열을 사용한다.
- 강한 상태를 약한 표현으로 속이지 않는다.
- 기능 대사는 현재 위험과 비교 기준을 짧게 말하고, 세계관 대사는 왜 그런 평가가 생겼는지 생활·전적·관계 속에서 보여준다.
- 현지화에서도 강도 단계와 집중·균형·변칙 같은 성향 차이가 유지되는지 검수한다.

이 패턴은 적 정보뿐 아니라 관계 상태, 조직 평판, 감염 단계, 신뢰도와 조사 진행에도 적용할 수 있다. 정밀 수치 비교가 핵심인 분석 화면에는 세계관 문구만 강제하지 않고 상세 숫자 보기나 개발·접근성 경로를 함께 제공한다.

관련 사례: `docs/knowledge/cases/DIEGETIC_OPPONENT_INFORMATION_CASE.md`

## 14. 소설 ↔ 게임 스토리 전이 경계

Coc-Fiction 같은 선형·연재 소설 작업에서 검증된 craft는 이후 게임 스토리 작업에 재사용할 수 있다. 다만 **공통 서사 원리**와 **매체 전용 실행 규칙**을 분리한다.

### 공통으로 재사용 가능한 것

- 인물의 욕망·두려움·판단 기준·행동 인과.
- 장면 목적, 장면 전후 변화, 갈등, setup/payoff.
- 정보 공개 순서, 미스터리, 복선·회수, 감정 리듬.
- 캐릭터 voice, 관계 변화, 대사의 subtext와 반복 방지.
- 사건 순서, 인물 위치·부상·소지품·지식 상태 같은 연속성.
- 장기 arc와 에피소드별 약속·회수.
- 구조→장면→문장→교정의 단계형 퇴고.

### 소설에서 별도로 보호할 것

- 문장 리듬, 문단 호흡, 시점, 내면 서술, 서술자 거리.
- 독자가 직접 조작하지 않는 상태에서의 정보 통제와 장면 전환.
- 작가가 고정한 사건 순서와 독서 속도.
- 선택지·상태 변수·UI를 반드시 만들 필요가 없음.

### 게임에서 추가할 것

- 플레이어 agency와 선택 가능한 행동.
- 선택·퀘스트·시스템 상태가 대사와 장면을 실제로 바꾸는 경계.
- branch budget, 합류 지점, replay, save/load, 중복 보상 방지.
- UI·입력·전투·탐색·경제·퀘스트가 narrative를 전달하는 방식.
- line ID·state ID·localization·voice-over·runtime data 계약.

### 전이 판정

```text
소설에서 반복 검증된 character / scene / continuity / revision 원리
→ 게임 스토리에는 ADAPT
→ player action·state·runtime과 연결해 TEST

게임의 choice/state/branch 규칙
→ 선형 소설에는 자동 강제하지 않음
→ 장면 인과·연속성에 도움이 되는 부분만 ADAPT
```

좋은 소설 장면이 자동으로 좋은 게임 장면은 아니며, 좋은 게임 분기가 자동으로 좋은 소설 구조도 아니다.

## 15. 단계형 퇴고와 연속성 검수

문장 polish를 먼저 반복해 구조적 문제를 숨기지 않는다. 기본 퇴고 순서는 다음과 같다.

```text
CANON_AND_CONTINUITY
→ DEVELOPMENTAL_STRUCTURE
→ SCENE_AND_CHARACTER
→ DIALOGUE_AND_INFORMATION
→ LINE_AND_PROSE
→ COPY_AND_PROOF
→ CROSS_RANGE_RECONCILIATION
```

### `CANON_AND_CONTINUITY`

- 사건 순서·날짜·장소·인물 생사·부상·소지품·관계·지식 상태를 정본과 대조한다.
- 이전 회차에서 확정된 사실을 새 문장 편의를 위해 뒤집지 않는다.
- 장기 연재는 현재 범위 앞뒤 경계와 파생 요약·continuity artifact를 재대조한다.

### `DEVELOPMENTAL_STRUCTURE`

- 장면·화·챕터의 존재 이유와 전후 변화를 본다.
- 인물이 plot에 끌려가기만 하지 않고 욕망·판단으로 행동하는지 본다.
- setup이 회수되고 payoff가 충분히 준비됐는지 본다.
- 같은 기능의 장면·정보·갈등이 반복되지 않는지 본다.

### `SCENE_AND_CHARACTER`

- POV/시점 인물이 실제로 보고 알고 느낄 수 있는 범위를 지킨다.
- 장면 목표·장애·결과가 행동으로 드러나는지 본다.
- 캐릭터 voice와 관계 거리가 현재 arc 상태와 맞는지 본다.

### `DIALOGUE_AND_INFORMATION`

- 설정 설명을 서로 이미 아는 인물의 설명 대화로 채우지 않는다.
- 독자/플레이어가 지금 알아야 할 정보와 나중에 알아야 할 정보를 구분한다.
- 대사마다 기능·관계·세계관 중 주 역할을 판정한다.

### `LINE_AND_PROSE`

- 의미 중복, 추상어 남용, 시점 흔들림, 리듬, 묘사 밀도를 다듬는다.
- 구조·캐릭터·연속성 문제가 남아 있으면 문장 polish를 완료로 보지 않는다.

### `COPY_AND_PROOF`

- 맞춤법·띄어쓰기·고유명사·호칭·문장부호·표기 통일을 검사한다.
- 교정 단계에서 설정·사건·관계 방향을 새로 바꾸지 않는다.

## 16. 완료 기준

- [ ] 장면의 중심 질문이 하나다.
- [ ] 대사를 가려도 기본 행동 흐름을 이해한다.
- [ ] 말투만으로 주요 인물을 구분한다.
- [ ] 설정은 행동·갈등·선택에 연결돼 있다.
- [ ] 게임 장면이라면 선택지가 서로 다른 태도·위험·정보를 가진다.
- [ ] 관계 변화가 숫자보다 반응으로 보인다.
- [ ] 실패와 후일담이 다음 판단이나 감정을 남긴다.
- [ ] 미확인 정보와 정답을 안내자가 누설하지 않는다.
- [ ] 게임이라면 반복 재생·저장 복구에서 보상과 기억이 중복되지 않는다.
- [ ] 소설이라면 시점·연속성·문장 리듬과 장기 arc가 정본에 맞는다.
- [ ] 구조·연속성 검수 전에 문장 polish만으로 완료 처리하지 않는다.
- [ ] 피해와 후유증을 가벼운 농담으로 소비하지 않는다.
