# 버티컬 슬라이스 통합 데모·4단계 Gate 계약

이 reference는 `designing-vertical-slices`의 제품 단계·통합 데모·플랫폼 준비가 현재 요청과 관련될 때만 읽는다.

## Release-near 플레이 검증 권위

```text
RELEASE_NEAR_VERTICAL_SLICE_FIRST
GAMEPLAY_VALIDATION_REQUIRES_SHIPPING_INTENT_SLICE
SYSTEM_ONLY_POC_NOT_PLAYER_EXPERIENCE_EVIDENCE
TECHNICAL_SPIKE_INTERNAL_ONLY
SHIPPING_INTENT_UI_IMAGE_AUDIO_VFX_SYSTEM_REQUIRED
EXISTING_SOLUTION_FIRST_ADAPT_TO_PROJECT
```

플레이어 경험을 판정하는 Gate 2 테스트는 짧더라도 실제 게임 사용 후보인 UI/UX, 이미지·아트, 사운드, VFX/피드백, 시스템·데이터·콘텐츠가 연결된 완성형 Vertical Slice를 대상으로 한다. 플레이어가 접하는 경로에 임시 `player-facing placeholder`나 dummy presentation이 남아 있으면 플레이 경험 판정 Gate를 통과시키지 않는다. 시스템-only PoC는 기술 질문의 내부 Spike일 뿐 재미·몰입·가독성·판매력·감정·기억의 증거가 아니다.

## 1. 제품 단계

```text
CONCEPT_APPROVAL
→ DEMO_FIRST_VERTICAL_SLICE
→ PRODUCTION_APPROVAL
→ RELEASE_CANDIDATE_APPROVAL

`PROTOTYPE_AND_VERTICAL_SLICE`는 과거 기록 호환 이름이며 새 작업에서는 `DEMO_FIRST_VERTICAL_SLICE`로 해석한다.
```

제품 단계, Work Mode, Gate 판정, 구현 사실을 혼용하지 않는다.

- 제품 단계: 현재 제품이 어떤 승인 프로그램에 있는가.
- Work Mode: 현재 작업자가 `PLAN / BUILD / REVIEW` 중 무엇을 수행하는가.
- Gate 판정: `APPROVED / APPROVED_WITH_CONDITIONS / REWORK / REPEAT_VALIDATION / HOLD / STOP / UNVERIFIED`.
- 구현 사실: `IMPLEMENTED / PARTIALLY_IMPLEMENTED / PLANNED / PROPOSED_ONLY / DEFERRED / REMOVED / UNVERIFIED`.

## 2. Gate 1 — 콘셉트 승인

### 목표

만들 가치가 있고 버티컬 슬라이스로 증명 가능한 게임인지 판정한다.

### 필수 산출물

- 플레이어 약속
- 목표 플레이어와 플레이 상황
- 프로젝트 코어·비타협 조건·변경 가능한 외피
- 뾰족한 재미와 핵심 선택
- Core Loop와 경험 곡선
- 세일즈포인트 최대 3개
- 플랫폼·입력·세션·팀·기간·예산·성능·접근성 제약
- 벤치마킹과 `ADOPT / ADAPT / AVOID / TEST / IGNORE`
- SWOT의 `SO / WO / ST / WT` 행동
- VRIO의 가치·희소성·모방 난도·1인 개발 조직화
- 세계관 마스코트 또는 상징 동반자 후보
- 데모 핵심 위험 등록부와 필요한 내부 `TECHNICAL_SPIKE` 후보
- 버티컬 슬라이스 후보와 포함·제외 범위
- Balance Tuning Backlog 초안

### 승인 조건

- 게임을 한 문장으로 설명할 수 있다.
- 반복 행동과 핵심 고민이 명확하다.
- 세일즈포인트가 실제 플레이와 짧은 영상·스크린샷으로 증명 가능하다.
- 유사 게임 대신 선택할 이유가 있다.
- 세계관·캐릭터·시스템·UI·사운드가 같은 방향을 가리킨다.
- 1인 개발 제약 안에서 대표 구간을 만들 수 있다.
- 핵심 기획 충돌이 해소됐다.
- 세부 수치는 플레이테스트 대상으로 분리됐다.

## 3. Gate 2 — 데모 우선 버티컬 슬라이스

### 연속 프로그램

```text
데모 계약·품질 기준 확정
→ shipping-intent UI/이미지/사운드/VFX/시스템/콘텐츠 통합
→ 제작 의도 Vertical Slice 구현
→ 통합 데모 QA
→ 내부 플레이테스트
→ 외부 플레이테스트·반응 조사
→ DEMO_VALIDATION
→ 본제작 판단 자료
```

별도 `CORE_POC` 제품 단계는 사용하지 않는다. 첫 통합 플레이 제품은 최종 방향에 가까운 아트·UI·UX·사운드·데이터·저장·복구·성능·접근성을 갖춘 **완성 품질 데모**다.

데모 전체를 차단하는 기술 불확실성이 있을 때만 Vertical Slice 내부에 제한된 `TECHNICAL_SPIKE`를 둔다. Spike는 별도 Gate나 공개 데모가 아니며, 질문 하나와 성공·실패·중단 기준을 갖고 결과를 데모 구현에 재사용하거나 Decision 근거로 기록한다.

`SLICE_VALIDATION`은 과거 호환 이름이며 새 작업에서는 내부·외부 플레이테스트와 반응 조사를 포함하는 `DEMO_VALIDATION`으로 해석한다. 위험한 가설을 완성 자산과 콘텐츠 양으로 덮지 않되, 저품질 폐기형 Prototype을 별도 마일스톤으로 승인하지 않는다.

### 대표 플레이 흐름

```text
첫인상
→ 첫 행동
→ 기본 규칙 학습
→ 첫 의미 있는 선택
→ 핵심 루프 완주
→ 성공 또는 실패
→ 복구·재도전
→ 성장·보상
→ 더 큰 가능성
→ 데모 종료
```

### 필수 품질

- 최종 방향에 가까운 아트·UI·UX
- 대표 음악·효과음과 무음 대안 피드백
- 저장·복귀·오류·실패 복구
- 일반 반복 콘텐츠와 기억에 남는 하이라이트
- 세계관 마스코트의 실제 역할
- 대표·최악 장면의 목표 플랫폼 성능
- 핵심 정보·입력·시간·난이도·모션 접근성 장벽
- 두 번째 유사 콘텐츠 제작 증거
- 빌드·버전·표본·테스트 증거

### Slice 추적표

| 요소 | WHY | 플레이어 행동 | 규칙·피드백 | 데모 장면 | 트레일러 | 스크린샷 | 테스트 지표 | 반복 제작 증거 |
|---|---|---|---|---|---|---|---|---|

추적되지 않는 요소는 범위에서 제거하거나 역할을 다시 정의한다.

## 6. Gate 2 판정

- `APPROVED`: 완성 품질 Slice 데모·내외부 플레이테스트·외부 검증·제작 반복성이 증명됨.
- `APPROVED_WITH_CONDITIONS`: 코어는 유효하며 명시된 수정 조건 뒤 본제작 판단 가능.
- `REWORK`: 코어 가설은 유지하되 루프·UX·표현·파이프라인 수정 필요.
- `REPEAT_VALIDATION`: 구간·표본·빌드·가설이 대표적이지 않음.
- `HOLD`: 자산·기술·예산·권한·플랫폼 의존성 대기.
- `STOP`: 재미·제품 약속·제작성 모두 성립하지 않음.
- `UNVERIFIED`: 실제 빌드·실행·표본·증거 없음.

## 7. Gate 3 — 본제작 승인

### 증거

- 목표 플레이어가 핵심 재미를 실제로 인식함
- 세일즈포인트가 기억되고 설명됨
- 첫 재미 시점과 튜토리얼 이탈이 허용 범위
- UI·UX·조작 장벽을 수정 가능
- 난이도 문제와 기획 문제를 구분함
- 콘텐츠 확장 시 루프가 유지됨
- 제작 속도·병목·외주·예산·기간 산정 가능
- Steam·STOVE·Playtest 또는 Google Play 테스트 반응이 유효함
- 텀블벅 진행 여부를 근거로 판단 가능
- 세부 수치를 반복 튜닝할 수 있는 데이터 구조가 있음

### 결과

- `APPROVED`: 코어와 범위 고정, 전체 Roadmap과 예산 확정.
- `APPROVED_WITH_CONDITIONS`: 조건부 수정 후 본제작.
- `REWORK`: Slice 일부 재설계 후 재검증.
- `REPEAT_VALIDATION`: 다른 구간·표본·빌드로 재검증.
- `HOLD`: 외부 의존성 해결 대기.
- `STOP`: 프로젝트 중단 또는 보류.

## 8. Gate 4 — 출시후보 승인

### 게임

- 시작부터 엔딩·장기 목표까지 정상 진행
- 임시 자산·테스트 기능 제거
- 주요 콘텐츠·저장 호환·경제·난이도 최종 검수

### 기술

- 치명적 오류 없음
- 해상도·화면비·입력·오디오·저장·오프라인
- 업데이트 후 저장 호환
- 성능·메모리·로딩·장시간 실행
- 목표 장치와 롤백 빌드

### 상점·법률

- 최종 트레일러·스크린샷·설명·가격·할인
- 등급·지원 언어·고객지원·개인정보처리방침
- 에셋·폰트·음악·플러그인·AI 자산 라이선스와 크레딧

### 운영

- 출시일 Runbook
- 긴급 패치·롤백
- 알려진 문제
- 리뷰·고객 문의·커뮤니티 공지
- 출시 후 대응 일정

실제 심사·빌드·테스트·권한 증거 없이 출시후보 승인을 기록하지 않는다.
