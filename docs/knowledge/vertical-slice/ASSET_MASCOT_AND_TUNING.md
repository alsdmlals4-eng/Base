# 에셋·UI·UX·사운드·마스코트·수치 조정 계약

이 reference는 버티컬 슬라이스에서 이미지·UI·사운드·플러그인·마스코트·밸런스 수치를 설계하거나 검수할 때만 읽는다.

## 1. 생성·조달 순서

```text
콘셉트와 플레이어 경험
→ UI·UX·사운드 역할 정의
→ 프로젝트 기존 승인 자산
→ 프로젝트 보유·구매 자산
→ Registry의 에셋·라이선스 Skill
→ Godot 기본 기능·공식 Asset Store·공식 GitHub·신뢰 가능한 마켓 조사
→ 라이선스·기술·스타일·성능 비교
→ ADOPT / ADAPT / TRIAL / REJECT / BUILD_CUSTOM
→ 적합한 자산이 없거나 코어 고유성이 필요할 때만 신규 생성
→ 실제 게임 적용
→ 런타임 화면·사운드·접근성·성능 재검수
```

유료 구매·계정 연결·프로젝트 설치는 사용자 승인 전 수행하지 않는다. 라이선스를 확인할 수 없는 자산은 사용하지 않는다.

## 2. UI 계약

- 화면 목적과 플레이어의 다음 행동
- 가장 먼저 읽어야 할 정보
- 상태·비용·위험·보상의 위계
- 입력 방식·버튼 크기·포커스·컨트롤러·터치
- 취소·되돌리기·실패·복구
- 화면 밀도·글자 크기·대비·색 외 대안
- 해상도·화면비·세이프 영역
- 세계관 재질·형태·모션과 정보 전달의 균형

UI 에셋팩은 표현 자산이며 UX 흐름과 정보 구조의 정본이 아니다.

## 3. UX 계약

```text
진입
→ 첫 행동
→ 선택
→ 확인
→ 시스템 반응
→ 성공·실패
→ 복구
→ 다음 목표
```

- 첫 행동까지 불필요한 단계가 적은가?
- 설명과 실제 행동이 연결되는가?
- 잘못된 입력과 전략적 실패가 구분되는가?
- 중복 입력·빠른 클릭·취소·중단·재시도 처리가 있는가?
- 메뉴 이동 뒤 현재 목표를 잃지 않는가?
- 반복 조작이 핵심 판단을 가리지 않는가?

## 4. 사운드 계약

- 음악의 감정 역할과 구간별 변화
- 환경음과 세계관 정보
- UI 선택·확인·취소·오류
- 행동·명중·피격·성공·실패·보상
- 위험 경고와 상태 변화
- 반복 재생 변형과 피로
- 음량 우선순위·루프·전환
- 무음·청각 제약 플레이어를 위한 시각·촉각 대안

사운드는 장식이 아니라 플레이 판정·감정·리듬의 피드백이다.

## 5. 세계관 마스코트

각 게임은 세계관과 장르에 어울리는 귀여운 마스코트 또는 상징 동반자 후보를 최소 1개 검토한다. 필수 구현이 아니라 **역할이 증명될 때만 Slice에 포함**한다.

가능한 역할:

- 세계관 진입 장벽을 낮추는 안내자
- 튜토리얼·경고·성공·실패 피드백
- 플레이어와 세계를 연결하는 정서적 접점
- 수집·성장·공방·기록 등 핵심 루프의 상징
- 스토어 아이콘·캡슐·커뮤니티 기억점
- 디지털 아트북·월페이퍼·스티커 등 후원 자산

공포 게임은 밝은 개그 캐릭터를 억지로 넣지 않는다. `귀엽지만 불길한`, `보호하고 싶지만 정체를 알 수 없는`, `기관의 낡은 안내 인형`, 무언의 작은 생물·장비 정령·엠블럼처럼 긴장을 유지할 수 있다.

### 디자인 최소 계약

```yaml
mascot_name_or_codename:
world_role:
player_relationship:
emotional_role:
gameplay_or_ui_role:
core_loop_connection:
visual_silhouette:
key_colors_and_materials:
default_state:
positive_state:
warning_or_failure_state:
voice_or_sound_identity:
store_and_marketing_role:
crowdfunding_role:
must_not_do:
```

### 제한

- 장황한 대사로 핵심 플레이를 대신 설명하지 않는다.
- 분위기와 긴장을 반복적으로 깨지 않는다.
- 모든 기능에 등장시켜 피로를 만들지 않는다.
- 마스코트를 위해 핵심 시스템 범위를 늘리지 않는다.
- 기존 유명 마스코트의 실루엣·성격·표현을 모방하지 않는다.
- 실제 등급과 대상 연령을 오인시키지 않는다.

### Slice 증거

- 실제 화면에서 읽히는 실루엣
- 세계관 내 존재 이유
- 한 가지 핵심 UI·피드백·스토리 역할
- 대표 감정 상태
- 트레일러·스크린샷·스토어 활용 가능성
- 플레이어가 기억했는지 묻는 테스트 질문

## 6. 수치·밸런스 상태

### `FIXED_CONTRACT_VALUE`

플랫폼·저장·Schema·ID·성능 예산처럼 기술 계약상 고정되어야 하는 값.

### `INITIAL_TEST_VALUE`

첫 구현·테스트를 위한 임시값. 최종 밸런스로 표현하지 않는다.

### `TUNING_RANGE`

정확한 값 대신 테스트 가능한 범위.

### `PLAYTEST_TUNING_REQUIRED`

실제 플레이 증거가 없어 확정하지 않는 값.

### `VALIDATED`

명시된 빌드·표본·지표에서 검증된 값. 조건이 바뀌면 재검토한다.

### `RETEST_REQUIRED`

규칙·콘텐츠·플랫폼·표본 변화로 다시 검증해야 하는 값.

## 7. 사용자에게 묻지 않는 값

- 개별 공격력·체력·방어력
- 개별 비용·보상·드롭률
- 개별 확률·쿨타임·지속 시간
- 사소한 애니메이션 시간
- 테스트로 결정 가능한 기본값

이 값은 기술 검수안과 Balance Tuning Backlog에 일괄 정리한다.

## 8. 사용자 결정이 필요한 값

값이 다음 제품 약속을 바꾸는 경우에만 `USER_DECISION_REQUIRED`다.

- 5분 세션과 30분 세션
- 실패 시 전체 진행 손실 여부
- 무료 광고형과 유료 완전판
- 접근성과 전략 밀도의 우선순위
- 경제·성장·과금의 핵심 구조
