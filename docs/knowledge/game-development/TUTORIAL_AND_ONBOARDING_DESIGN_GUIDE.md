```yaml
guide_role: tutorial-and-onboarding-design-method
execution_owner: analyzing-and-refining-game-concepts
default_mode: tutorial-and-onboarding-design
research_coverage_owner: governing-game-user-research-coverage
```

## 목적과 경계

튜토리얼은 조작 설명·팝업·강제 클릭의 집합이 아니다. 플레이어가 프로젝트의 실제 핵심 규칙을 수행하고, 문제와 필요를 이해하고, 해결 방법을 발견·적용하고, 성장 전후의 행동 차이를 체감한 뒤, 안내 없이 다시 수행하고 다른 상황에 재사용하도록 설계한다.

```text
프로젝트 정본·실제 코드·데이터·UI·테스트 감사
→ RULE → NEED → DISCOVER → FEEL → PROVE → TRANSFER
→ 플레이테스트·텔레메트리 → 적대적 검토 → 결정
```

이 Guide는 공용 방법과 검증 계약만 소유한다. 세계관·수치·Scene·Resource·실제 구현 상태는 대상 프로젝트 정본과 실제 파일이 소유한다. 프로젝트 정본 또는 실제 구현을 확인할 수 없으면 `BLOCKED_UNVERIFIED`로 남기며, 외부 사례나 AI 추론으로 그 빈칸을 채우지 않는다.

## 프로젝트 선감사

튜토리얼 화면이나 대사를 먼저 만들지 않는다. 최신 사용자 지시, 프로젝트 `AGENTS.md`, Active Context, 확정 Decision과 현재 GDD를 읽고, 구성된 Google Sheets가 있으면 현재 계획·진행도와 `PROPOSED_SHEET_CHANGE`를 비교한다. 이어 실제 코드·데이터·Scene·Resource·UI·입력·테스트, 동일 Goal의 열린·최근 병합 PR, 기존 도움말과 첫 세션 데이터를 확인한다.

학습 목표마다 플레이어 행동, 필요한 정보, 시스템 반응, 성공·실패 증거, 복구 경로, 독립 수행, 전이 상황을 연결한다. 정적 조작표를 읽거나 팝업을 닫은 것은 학습 성공이 아니다.

## 학습 사다리

### RULE — 기본 규칙 수행

한 구간에는 하나의 핵심 학습 목표를 우선하고, 첫 의미 있는 행동과 피드백을 계정·상점·알림보다 먼저 제공한다. 본편과 다른 임시 규칙·무적·수치가 필요하면 차이와 제거 시점을 기록한다.

### NEED — 필요·결핍 인식

현재 능력으로 해결하기 어렵거나 비효율적인 실제 장벽을 보여 주고, 플레이어가 원인과 손실을 이해하게 한다. 상점·과금을 소개하기 위한 **강제 패배**, 보이지 않는 규칙, 고정 결과, 회복 불가능 손실로 만든 가짜 결핍은 금지한다. 문제 전 예고·대응 기회·재시도·복구를 제공한다.

### DISCOVER — 해결 방법 발견

문제를 인식한 뒤 필요한 성장·도구·규칙·정보를 공개하고, 플레이어가 획득·선택·장착·적용·사용 중 실제 핵심 행동을 수행하게 한다. 무엇을 누르는가뿐 아니라 왜 지금 필요한가와 언제 다시 쓰는가를 연결한다.

### FEEL — 성장 전후 차이 체감

```text
성장 전 기준 행동 ↔ 성장 후 비교 가능한 행동
```

시간·자원·위험·선택·경로·가능성 중 하나 이상이 실제로 변해야 한다. 숫자·이펙트·팝업만 커지고 행동과 결과가 같은 **가짜 성장**, 또는 성장 직후 자동 보정으로 성취를 지우는 경우는 학습 완료가 아니다.

### PROVE — 안내 없는 독립 수행

시범·명확한 안내 → 제한된 선택 → 힌트가 있는 유사 문제 → **안내 없는 독립 수행**으로 안내를 줄인다. 한 번의 우연한 성공만으로 숙련을 확정하지 않으며, 막힘에는 단계적 힌트와 복습 경로를 제공한다.

### TRANSFER — 다른 상황에서 재사용

다른 적·상황·조합·레벨·세션에서 같은 원리를 적용하게 한다. 표면만 다른 문제와 실제 전이를 구분하고, 장기 미접속 뒤 필요한 규칙·목표·진행을 다시 확인할 수 있게 한다. 전이 실패는 문구 문제가 아니라 규칙 일관성·피드백·난이도·정보 구조·기억 부담 문제일 수 있다.

## Skip·복습·복귀·접근성

- Skip 후에도 도움말·목표·조작·연습 경로를 다시 열 수 있어야 한다.
- 복습은 정적 조작표만이 아니라 짧은 시연·연습·맥락 예시를 제공한다.
- 복귀 플레이어는 전체 강제 튜토리얼이 아니라 필요한 개념만 재학습한다.
- 핵심 정보는 음성, 색, 시간 제한, 단일 입력 하나에만 의존하지 않는다. 자막·텍스트·시각 신호·입력 대안·일시정지/시간 조절·명확한 Focus를 검토한다.

접근성 옵션의 존재만으로 통과를 선언하지 않는다. 실제 대상 플레이어·입력·플랫폼에서 장벽과 **접근성 대체 채널**을 검증한다.

## 플레이 경험·숙련도 Segmentation

같은 튜토리얼이라도 일반 게임 숙련도에 따라 탐색·완료·실험·즐거움과 막힘이 달라질 수 있다. 완료율 평균만으로 초보자와 숙련자의 경험 차이를 지우지 않는다.

```yaml
prior_game_expertise:
expertise_measure:
novice_expert_segment:
expertise_by_onboarding_interaction:
```

`prior_game_expertise`는 플레이 시간 하나로 고정하지 않는다. 프로젝트에 맞게 장르 경험, 입력 장치 경험, 유사 규칙 경험, 주당 플레이 시간, 누적 연수, 자기보고와 관찰 행동을 구분한다. `expertise_measure`의 한계와 self-report bias를 기록한다.

```text
novice average != expert average
more completed levels != learned core principle
exploratory tinkering != random input by default
one commercial puzzle game study != universal onboarding law
```

외부 연구는 `ADAPT` 또는 `TEST` 입력이다. 실제 프로젝트에서는 최소 novice/expert segment별 첫 의미 행동, 힌트 의존, 탐색, 독립 수행, 전이, 이탈을 비교하고 `expertise_by_onboarding_interaction`이 재현되는지 검증한다. 차이가 없거나 다른 변수가 더 강하면 공용 규칙으로 승격하지 않는다.

## 근거·검증·적대적 검토

벤치마크는 기능·화면·대사 복사가 아니라 현재 결정 질문을 검증하는 도구다. 출처·버전·관찰 사실·작동 원리·실패 조건·프로젝트 적합성을 기록하고 `ADOPT / ADAPT / AVOID / TEST / IGNORE`로 판정한다. 공식 접근성 가이드와 현업 사례는 프로젝트 정본이나 실제 구현 사실을 대체하지 않는다.

완료율만으로 이해·숙련·성장 체감·접근성을 판정하지 않는다. 일반 게임 숙련도·장르 경험·입력 경험을 segment로 분리하고 평균이 novice/expert의 반대 문제를 숨기지 않는지 확인한다. 첫 의미 있는 행동, 단계 진입·실패·재시도, 힌트·도움말 재열람·Skip, 독립 수행·전이 성공, 이탈을 **텔레메트리**와 관찰·인터뷰로 분리해 수집한다. 성공·중단 기준은 결과 전에 선언하며, 실제 빌드·대상 집단·과제·관찰 없이 사람 검증을 완료로 보고하지 않는다.

적대적 검토에서는 본편과 다른 튜토리얼 규칙, 정적 조작표 오판, 문제 인식 전 해결책 광고, 강제 패배·가짜 결핍·가짜 성장, 여러 개념 동시 교육, 완료율·한 번의 성공만으로 숙련 확정, novice/expert 차이와 expertise-by-onboarding interaction 누락, 독립 수행·전이·Skip·복습·복귀·접근성 대체 채널 누락, 벤치마크를 정본처럼 복제하는 행위를 공격한다. 검증된 finding만 `MUST_FIX`, `SHOULD_FIX`, `DEFER`, `REJECTED_CRITIQUE`, `BLOCKED_UNVERIFIED`로 판정한다.

## 완료 Gate

설계 단계는 프로젝트 정본·실제 구현을 감사하고, `RULE → NEED → DISCOVER → FEEL → PROVE → TRANSFER`를 행동과 피드백으로 연결하며, 성장 전후 비교·Skip/복습/복귀·접근성·벤치마크·플레이테스트를 계약으로 만들었을 때만 닫는다. 이는 엔진 구현, 사람 플레이테스트, 런타임 접근성·성능 검증 완료를 뜻하지 않는다.
