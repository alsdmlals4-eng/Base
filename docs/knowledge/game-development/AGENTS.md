# Scoped Game-Development Knowledge Routing

This file applies to `docs/knowledge/game-development/**`.

## Notion approved visual delivery

For any task that stores, replaces, migrates, hands off, or verifies an **approved image/visual in Notion**, read and apply these references before declaring delivery complete:

1. `NOTION_APPROVED_ORIGINAL_FIRST_GATE.md`
2. `NOTION_GPT_VISUAL_LAYOUT_CONTRACT.md`
3. `../methods/NOTION_OFFICIAL_PRODUCT_OPERATING_REFERENCE.md`
4. `NOTION_VISUAL_ASSET_AND_FLOW_WORKFLOW.md` when visual lifecycle/placement is in scope

For approved visual delivery, `NOTION_APPROVED_ORIGINAL_FIRST_GATE.md` is the narrow priority rule if older/general preview-master wording could be read as making a reduced preview the normal completion artifact.

Required default:

```text
canonical approved original
→ pixel dimensions + file size + Hash when available
→ detect chat/intermediate re-encoding
→ reacquire canonical source bytes when byte fidelity matters
→ Notion-owned original upload/attach
→ destination readback
→ human Original/client-visible verification separately when required
```

Do not treat a low-resolution preview, external URL, chat-reencoded file, filename, or upload-only status as canonical-original delivery completion.

- `DISPLAY_PREVIEW_ONLY` is an explicit display/fallback derivative.
- `BYTE_ORIGINAL != PIXEL_EQUIVALENT`.
- `HIGH_RES_NOTION_SERVER_PASS != HIGH_RES_NOTION_PASS`.
- Preserve `POST_STORAGE_HASH_READBACK_NOT_AVAILABLE` and `HUMAN_ORIGINAL_VIEW_NOT_RUN` when those checks cannot actually be executed.
- Historical preview-only records may remain as evidence, but active reuse must route through `LEGACY_PREVIEW_NEEDS_ORIGINAL` until canonical original promotion is completed.

Do not create a second dashboard, paid automation service, or image-delivery authority to satisfy this routing rule. Reuse the currently verified Notion/connector/file-upload path first and keep general Notion product/layout semantics owned by the references above.
