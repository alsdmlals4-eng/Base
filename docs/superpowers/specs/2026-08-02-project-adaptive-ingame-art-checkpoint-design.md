# 프로젝트 적응형 인게임 아트 중간점검 설계

- 상태: `APPROVED_DESIGN`
- 기준 Base main: `896d2e6fd257084b6aa29b1703cd0bbfa3b18daa`
- Work Mode: `PLAN → BUILD → REVIEW`
- 공용 산출물: `templates/prompts/PROJECT_ADAPTIVE_INGAME_ART_CHECKPOINT_PROMPT.md`
- 주 Skill: `designing-art-prompts-and-technique-cards: intermediate-visual-checkpoint`
- 지원 Skill: `managing-project-intake-and-work-contract`, `auditing-and-refining-ui-art`, `running-adversarial-review-and-refinement`
- 신규 광역 Skill: 추가하지 않음

## 1. 목적

Base를 적용한 어떤 게임 프로젝트에서도 고정된 RPG 화면 세트를 먼저 강요하지 않고, 프로젝트의 최신 정본·구현·자산·PR을 조사한 뒤 그 프로젝트의 고유한 플레이 경험을 대표하는 장면을 선정하고 인게임 이미지 보드로 제작한다.

사용자에게는 내부 분석표나 프롬프트를 최종 결과처럼 보여주지 않는다. 장면 구성 승인 전에는 이미지를 만들지 않으며, 승인 후 내부 생성·검수·수정 과정을 거쳐 최종 검토를 통과한 이미지 보드만 우선 제공한다.

## 2. 검증에서 확인된 문제

십보강호 시험 적용 중 프로젝트를 충분히 파악하지 않은 채 일반 판타지 RPG 콜라주를 생성했다. 이 결과에는 프로젝트 코어인 1대1 10칸 전장, 3/3/4 수 계획, 공개 단서 기반 추론, 합·중단·복기, 수묵 무협, 강호행로가 충분히 반영되지 않았다.

재분석 후 다음 순서가 유효함을 확인했다.

```text
프로젝트 정본·PR·구현·자산 조사
→ 핵심 경험과 화면 흐름 복원
→ 장면 후보와 화면 구성안 작성
→ Grill Me로 사용자 승인
→ 개별 장면 이미지 생성
→ 동일 게임 일관성 검수
→ 적대적 검토와 회귀 재점검
→ 승인된 장면을 보드로 편성
→ 사용자에게 최종 이미지 보드만 제공
```

십보강호에서는 메인, 시작 무공 선택, 무공 구성·성장, 강호행로, 비무 브리핑·전투 준비, 기본 전투, 합 연출, 절초 연출, 묶음 복기, 전투 종료·보상·재도전이 도출됐다. 이 목록은 공용 고정 세트가 아니라 프로젝트 적응형 선정 결과의 예시다.

## 3. 책임 경계

### Base가 소유하는 것

- 프로젝트 선조사 절차
- 장면 선정 기준
- Grill Me 승인 Gate
- Screen Brief 구조
- 증거 수준과 상태 토큰
- 이미지 생성·검수·보드 편성 절차
- 적대적 검토·회귀 재점검
- 사용자 최종 출력 규칙

### 대상 프로젝트가 소유하는 것

- 세계관·캐릭터·게임 코어·핵심 루프
- 현재 화면 흐름과 Decision
- 실제 구현된 Scene·Script·Resource·데이터·자산
- 승인된 아트·UI·카메라·입력 방식
- 프로젝트별 핵심 장면 목록
- 최종 이미지 승인과 실제 자산 승격

## 4. 프로젝트 이해 선행 Gate

이미지 생성 전에 최소한 다음을 확인한다.

1. 최신 사용자 지시
2. Base 기준과 프로젝트 Base Adapter
3. 프로젝트 `AGENTS.md`, `START_HERE`, `ACTIVE_CONTEXT`, `DOCUMENTATION_MAP`
4. 최신 승인 Decision과 분야별 책임 원본
5. 실제 코드·데이터·Scene·Resource·자산·테스트
6. 동일 Goal의 열린 PR과 최근 병합 PR
7. 기존 승인 이미지·실제 런타임 캡처·현행 UI
8. 구현 완료, 승인 기획, 추론, 제안, 자리표시자의 구분
9. 보류·폐기·대체된 과거 설계

프로젝트 코어와 핵심 플레이 루프를 행동 단위로 복원하지 못하거나, 장면 근거를 정본·PR·실제 파일에 연결하지 못하면 `MISSING_CANON` 또는 `BLOCKED_UNVERIFIED`로 중단한다.

## 5. 장면 선정과 Grill Me Gate

분석 뒤 곧바로 이미지를 생성하지 않는다. 먼저 장면 후보를 다음 기준으로 평가한다.

- 핵심 경험 직접성
- 프로젝트 고유성
- 실제 플레이 화면으로서의 시각성
- 플레이 여정의 연결성
- 정본·구현·자산 근거
- 현재 단계에서의 표현 가능성
- 다른 장면과의 중복
- 한 보드에서의 판독성

그 결과로 `필수`, `확장`, `통합 가능`, `제외` 장면을 작성한다. 사용자에게 한 번에 결정 가능한 화면 구성안을 Grill Me 형식으로 제시하고, 명시적 승인 전에는 이미지 생성을 금지한다.

## 6. 이미지 생성과 보드 편성

각 승인 장면은 먼저 독립적인 Screen Brief를 갖는다.

- 화면 목적
- 첫 시선
- 플레이어의 중심 행동
- 핵심 정보
- 플랫폼·비율·입력
- 위험·비용·보상
- 성공·실패·복구
- 연결되는 이전·다음 화면
- 캐릭터·배경·UI·카메라·아트 고정 요소
- 근거 수준과 미확정 요소

개별 장면을 생성하고 일관성을 검수한 뒤 보드로 편성한다. 화면 밀도가 높거나 장면이 7개 이상이면 기본적으로 2개 보드로 나누되, 프로젝트 흐름과 사용자 승인에 따라 1개 또는 3개 이상도 허용한다.

권장 2개 보드 구분은 다음이다.

```text
Board A: 진입·준비·구성·여정
Board B: 핵심 플레이·결정적 연출·복기·결과
```

이 구분 역시 프로젝트마다 재설계한다.

## 7. 증거와 상태

각 요소는 내부 기록에서 다음으로 구분한다.

- `CURRENT`: 현재 정본·구현·승인 자산으로 확인됨
- `INFERRED`: 여러 근거에서 합리적으로 재구성했으나 직접 확정되지 않음
- `PROPOSED`: 이번 중간점검에서 새로 제안함
- `PLACEHOLDER`: 정보 부족을 숨기지 않기 위한 임시 표현

이미지는 기본적으로 `DRAFT_VISUAL`이며 최종 자산, 구현 완료, 런타임 검증으로 주장하지 않는다. 정본과 구현이 다르면 `CANON_CONFLICT`, 시각 표현이 정본과 충돌하면 `VISUAL_CANONICAL_CONFLICT`로 차단한다.

## 8. 적대적 검토 루프

이미지 생성 전 장면 구성에 `attack → validate-critique → decision-report`를 수행한다. 이미지 생성 후에는 승인된 Finding만 수정하고 `regression-recheck`를 수행한다.

주요 공격 질문:

- 다른 게임에도 그대로 붙일 수 있는 일반 장면으로 변질됐는가
- 프로젝트 고유 재미가 첫눈에 보이는가
- 구현되지 않은 기능을 완성된 화면처럼 꾸몄는가
- 폐기·대체된 설계를 부활시켰는가
- 카메라·입력·전장·UI 구조를 왜곡했는가
- 캐릭터·배경·UI·색·재질·광원·시대감이 같은 게임처럼 유지되는가
- 합·절초처럼 프로젝트의 결정적 순간을 일반 공격 효과로 축소했는가
- 텍스트와 장식이 실제 플레이 정보보다 앞서는가
- 한 보드에 과도하게 압축해 핵심 화면을 읽을 수 없게 만들었는가

Finding은 `MUST_FIX`, `SHOULD_FIX`, `USER_DECISION_REQUIRED`, `DEFER`, `REJECTED_CRITIQUE`, `BLOCKED_UNVERIFIED`로 분류한다.

## 9. 사용자 최종 출력

내부 분석, 장면 평가표, Screen Brief, 프롬프트, 상태표, 적대적 검토 기록은 작업 증거로 보존하되 기본 사용자 출력으로 내보내지 않는다.

사용자에게는 다음을 우선 제공한다.

```text
최종 검토를 통과한 인게임 이미지 보드
```

이미지 안에는 작업 과정, 분석 보고서, 체크리스트, 긴 구현 명세, 프롬프트 원문을 넣지 않는다. 사용자가 검토 기록이나 근거를 요청했을 때만 별도로 제공한다.

## 10. 비목표

- 모든 프로젝트에 메인·전투·인벤토리·결과 화면을 고정 강제
- 새 광역 Art Skill 추가
- 이미지 생성만으로 최종 프로젝트 자산 승인
- 프로젝트 정본보다 장르 관습이나 외부 레퍼런스를 우선
- 한 번의 대형 프롬프트로 모든 장면을 동시에 생성하고 일관성을 추정
- 이미지 생성 전 Grill Me 승인을 생략

## 11. 완료 조건

- 공용 Prompt가 프로젝트 선조사와 PR 점검을 강제한다.
- 장면 구성안에 대한 Grill Me 승인 전 이미지 생성을 차단한다.
- 고정 화면 세트가 아닌 프로젝트 적응형 장면 선정을 요구한다.
- 개별 이미지 생성 후 보드 편성과 2개 보드 밀도 기본값을 지원한다.
- 합·절초 등 프로젝트별 결정적 연출 장면을 별도 후보로 평가한다.
- 적대적 검토·회귀 재점검·증거 상태·최종 이미지 전용 사용자 출력을 포함한다.
- Registry와 기존 Skill ID를 변경하지 않는다.
