# GitHub + Solo Game-Dev Source Seeds — Design

**Date:** 2026-08-11
**Base baseline:** `23d5b292f619022cdd8ab7a33fb1debc2d294861`

## Goal

Add GitHub and the user-nominated `@zang_gamedev` YouTube channel to the periodic Base research intake without inflating either source into authority before repeated value and source context are verified.

## Existing Solution First

The current `PERIODIC_EXTERNAL_SOURCE_WATCHLIST.md` already owns source roles, evidence ceilings, original-source backtrace, and the new-site promotion gate. It already contains GitHub Copilot official docs and GitHub Actions / Code Security official docs, so a new broad `GitHub authority` source would duplicate existing owners and wrongly mix GitHub-hosted third-party repositories with GitHub's own product documentation.

The bounded design is therefore an **active discovery-seed addendum**, not a new Skill or a second evidence canon.

## Source 1 — GitHub repositories as a discovery surface

`GitHub` is treated as a cross-domain `DISCOVERY_FEED` surface for repository search, releases, tags, issues, pull requests, discussions, examples, templates, tools, and implementation references.

Evidence boundary:

- GitHub hosting, stars, forks, trending position, or activity alone do not raise Evidence tier.
- An official upstream repository can be primary evidence for its own code/release state only after owner, repository identity, branch/tag/release and version are verified.
- A third-party repository remains context-limited until maintenance, license, permissions, compatibility, security provenance, tests and actual consumer fit are checked.
- Open issue / pull request / discussion is not shipped behavior.

## Source 2 — `@zang_gamedev` as a solo-developer seed

User-nominated seed: `https://www.youtube.com/@zang_gamedev`.

The channel is an active `PROFESSIONAL_PRACTICE` / `DISCOVERY_FEED` seed for solo-development workflow, devlog communication, implementation examples, scope trade-offs, marketing communication and creator process observations.

The current environment could not reliably index/fetch the channel corpus, so no subscriber count, upload count, team-size claim, project claim, or specific video claim is promoted as verified fact by this change. Those remain `BLOCKED_UNVERIFIED` until an actual scan can read the channel/video surfaces.

## Shorts vs long-form handling

The scan must preserve format context rather than mixing all video evidence:

- **Shorts:** fast discovery of hooks, progress beats, visual demonstrations, concise implementation or production signals. Treat as a lead; follow through to a longer explanation, repository, release note, project page, or other primary source where material.
- **Long-form videos/devlogs:** better candidate surface for workflow rationale, constraints, chronology, implementation context, postmortem and trade-off discussion. Still creator self-report/professional practice, not universal law.
- Do not compare Shorts and long-form using one universal success threshold. Current YouTube official guidance exposes format-specific analytics and explicitly recommends same-type comparison because audience behavior differs across formats.

## Expansion to other solo developers

`@zang_gamedev` is a seed, not an exclusive creator. Periodic scans may nominate other solo/small-team game-development channels when they provide repeated relevant material. Each additional permanent source must pass the existing new-site gate, including repeat value, overlap, commercial interest, source access/backtrace and an owner/consumer candidate.

Do not create a quota of creators, scrape viral clips into canon, or treat views/subscribers as evidence authority.
