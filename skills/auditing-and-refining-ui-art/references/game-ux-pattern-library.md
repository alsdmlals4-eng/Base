# 게임 UX 패턴 라이브러리

패턴은 화면 모양이 아니라 반복되는 플레이어 문제의 해결 계약이다. 프로젝트는 필요한 패턴만 `ADOPT / ADAPT / AVOID / TEST / IGNORE`로 판정한다.

## 공통 카드 필드

```yaml
pattern_id:
problem:
player_risk:
use_when:
do_not_use_when:
core_flow:
required_states:
feedback_channels:
accessibility_fallbacks:
platform_adaptation:
failure_modes:
validation_predicates:
```

---

## UXP-STATUS-VISIBILITY — 시스템 상태 가시성

- **문제:** 플레이어가 현재 단계·선택·처리 상태를 추측한다.
- **위험:** 중복 입력, 진행 불신, 실패 원인 오해.
- **사용:** 저장, 로딩, 턴/웨이브, 선택, 대기, 잠금, 결과 처리.
- **흐름:** 현재 상태 → 가능한 행동 → 처리 중 → 결과 → 다음 상태.
- **상태:** idle, selected, pending, success, warning, error.
- **채널:** 텍스트·형태·아이콘·수치 변화·필요 시 음향.
- **실패:** 애니메이션만 재생하고 결과가 안 보임, 로딩과 멈춤 구분 불가.
- **검증:** 플레이어가 현재 상태와 다음 행동을 5초 안에 설명한다.

## UXP-ACTION-FEEDBACK — 입력 접수와 즉각 피드백

- **문제:** 입력이 접수됐는지 알 수 없다.
- **위험:** 연타, 오작동 인식, 중복 구매/실행.
- **흐름:** 입력 → 즉시 접수 신호 → 처리 상태 → 성공/실패 → 다음 행동.
- **상태:** pressed, pending, resolved, rejected.
- **폴백:** 진동·소리 없이도 버튼 상태·텍스트·결과 영역 변화가 남는다.
- **실패:** 화려한 효과가 입력 접수와 결과 원인을 구분하지 못함.
- **검증:** 단일 입력과 중복 입력에서 결과 횟수가 예상과 일치한다.

## UXP-PREDICT-BEFORE-COMMIT — 실행 전 비용·위험·결과 예측

- **문제:** 되돌리기 어려운 행동을 결과를 모른 채 실행한다.
- **위험:** 불공정 인식, 빌드 손상, 자원 낭비.
- **흐름:** 후보 선택 → 비용/조건/예상 변화 → 불확실성 표시 → 실행 → 실제 결과 비교.
- **상태:** valid, invalid, risky, irreversible, uncertain.
- **폴백:** 색상 외에 숫자·문구·아이콘·전후 비교를 제공한다.
- **실패:** 확률이나 조건을 보장처럼 표현, 숨은 비용.
- **검증:** 실행 전 플레이어가 잃고 얻는 것과 불확실성을 설명한다.

## UXP-PROGRESSIVE-DISCLOSURE — 점진적 공개

- **문제:** 첫 화면에서 너무 많은 규칙과 도구를 노출한다.
- **위험:** 인지 과부하, 핵심 행동 이탈.
- **흐름:** 현재 목표 → 필요한 최소 정보 → 행동 → 즉시 결과 → 다음 층 공개 → 재열람.
- **상태:** hidden, hinted, available, opened, remembered.
- **폴백:** 숨겨진 기능이 진행을 막지 않으며 재열람 경로가 있다.
- **실패:** 핵심 기능을 영구적으로 숨김, 기존 저장의 도구를 다시 접음.
- **검증:** 신규 플레이어의 첫 과제 완료와 복귀 플레이어의 기능 재발견을 분리 측정한다.

## UXP-COMPARABLE-CHOICES — 비교 가능한 선택지

- **문제:** 선택지마다 정보 위치·단위·표현이 달라 비교가 어렵다.
- **위험:** 선택 피로, 숫자 암기, 무작위 선택.
- **흐름:** 공통 비교 축 → 차이 강조 → 상세 → 선택 → 선택 이유 확인.
- **상태:** candidate, current, improved, worse, incomparable.
- **폴백:** 상승/하락은 색 외에 부호·화살표·텍스트를 사용한다.
- **실패:** 장점만 강조하고 비용·제약을 숨김.
- **검증:** 플레이어가 두 후보의 핵심 trade-off를 설명한다.

## UXP-SAFE-REVERSAL — 취소·되돌리기·안전한 파괴 행동

- **문제:** 실수가 영구 손실로 이어진다.
- **위험:** 불안, 행동 회피, 지원 요청.
- **흐름:** 행동 → 가능한 경우 즉시 실행+되돌리기 → 불가역이면 결과 중심 확인 → 완료/취소.
- **상태:** reversible, undo-window, irreversible, cancelled.
- **폴백:** 시간 제한 실행 취소에는 키보드/포인터 경로와 충분한 표시가 있다.
- **실패:** 모든 행동에 확인창, ‘예/아니오’만 제공, 결과를 말하지 않음.
- **검증:** 실수 과제에서 플레이어가 손실 없이 복구한다.

## UXP-ERROR-RECOVERY — 오류 원인과 복구

- **문제:** “불가능”만 표시하고 해결법을 주지 않는다.
- **위험:** 규칙 오해, 진행 중단.
- **흐름:** 실패 행동 → 원인 → 영향 → 가능한 다음 행동 → 재시도 결과.
- **상태:** blocked, missing-resource, invalid-target, conflict, recoverable, fatal.
- **폴백:** 오류 코드만 표시하지 않고 플레이어 언어로 설명한다.
- **실패:** 오류가 사라지는 시간이 짧거나 로그에만 남음.
- **검증:** 도움 없이 실패 원인을 수정해 같은 과제를 완료한다.

## UXP-FOCUS-NAVIGATION — 포커스·탐색·입력 동등성

- **문제:** 마우스 없이 메뉴를 완주할 수 없거나 포커스가 사라진다.
- **위험:** 입력 장벽, 잘못된 선택, 팝업 갇힘.
- **흐름:** 화면 진입 포커스 → 예측 가능한 이동 → 활성화/취소 → 팝업 → 이전 의미 위치 복귀.
- **상태:** focused, unfocused, disabled, modal, restored.
- **폴백:** 포커스는 색 외에 테두리·형태·크기/아이콘 중 동등 신호를 둔다.
- **실패:** 시각 순서와 이동 순서 불일치, 비활성 항목에 갇힘.
- **검증:** 선언된 입력 장치마다 게임 시작→핵심 행동→일시정지→복귀→종료를 완주한다.

## UXP-MULTI-CHANNEL-CUES — 다중 채널 의미 전달

- **문제:** 중요한 상태가 색·소리·모션 하나에만 의존한다.
- **위험:** 상태 누락, 잘못된 대응.
- **흐름:** 사건 → 주 신호 → 동등 보조 신호 → 기록/재열람.
- **상태:** informational, warning, critical, resolved.
- **폴백:** 색=텍스트/형태, 소리=자막/아이콘, 모션=정적 변화/로그.
- **실패:** 장식 효과를 정보 채널로 오인.
- **검증:** 각 채널을 하나씩 끈 상태에서도 의미와 긴급도를 구분한다.

## UXP-RETURNING-PLAYER-MEMORY — 복귀 플레이어 기억 보조

- **문제:** 며칠 뒤 복귀한 플레이어가 목표·규칙·최근 선택을 잊는다.
- **위험:** 저장 포기, 튜토리얼 재시작, 잘못된 선택.
- **흐름:** 복귀 → 최근 변화/현재 목표 → 핵심 규칙 → 다음 행동 → 상세 재열람.
- **상태:** new-session, resumed, changed-since-last, unresolved.
- **폴백:** 자동 요약을 건너뛰거나 다시 열 수 있다.
- **실패:** 긴 줄거리만 제공하고 현재 행동을 말하지 않음.
- **검증:** 일정 공백 뒤 플레이어가 1분 내 현재 목표와 다음 행동을 설명한다.

## UXP-CAUSAL-RECAP — 결과 인과와 복기

- **문제:** 결과는 보이지만 왜 발생했는지 알 수 없다.
- **위험:** 학습 불가, 운/불공정 인식, 전략 개선 실패.
- **흐름:** 선택/상태 → 사건 순서 → 중간 변화 → 최종 결과 → 다음 전략 단서.
- **상태:** event, modifier, prevented, consumed, final.
- **폴백:** 연출을 건너뛰어도 텍스트·아이콘·수치 순서가 남는다.
- **실패:** 최종 피해/보상만 표시, 원인 로그가 기술 용어뿐.
- **검증:** 플레이어가 결과 원인과 다음에 바꿀 행동을 설명한다.

## UXP-EMPTY-LOCKED-FALLBACK — 빈 상태·잠금·누락 폴백

- **문제:** 콘텐츠 없음, 잠금, 데이터/자산 누락이 빈 화면이나 오작동처럼 보인다.
- **위험:** 기능 불신, 진행 불가.
- **흐름:** 상태 감지 → 상태명/이유 → 가능한 행동 → 해제/복구 조건 → 정상 전환.
- **상태:** empty, locked, unavailable, missing-asset, offline, recovered.
- **폴백:** 이미지가 없어도 텍스트·도형·기본 아이콘으로 기능이 유지된다.
- **실패:** 잠금 조건 미표시, 빈 목록에 추가 방법 없음.
- **검증:** 각 비정상 fixture에서 플레이어가 상태와 다음 행동을 구분한다.

---

## 조합 규칙

- `UXP-PREDICT-BEFORE-COMMIT`은 `UXP-COMPARABLE-CHOICES`와 함께 쓰되 정보 중복을 줄인다.
- `UXP-PROGRESSIVE-DISCLOSURE`는 `UXP-RETURNING-PLAYER-MEMORY` 없이 적용하면 복귀 시 기능을 잃을 수 있다.
- `UXP-ACTION-FEEDBACK`은 결과 원인 학습이 필요한 게임에서 `UXP-CAUSAL-RECAP`으로 이어진다.
- `UXP-FOCUS-NAVIGATION`과 `UXP-MULTI-CHANNEL-CUES`는 모든 핵심 화면의 기본 검토 대상이다.
- 파괴적 행동은 `UXP-SAFE-REVERSAL`, 실행 불가 행동은 `UXP-ERROR-RECOVERY`를 우선한다.

## 패턴 승격 조건

프로젝트 사례를 Base 패턴으로 승격하려면 최소 다음이 필요하다.

1. 둘 이상의 프로젝트 또는 반복 작업에서 같은 문제가 확인됨.
2. 문제와 해결을 프로젝트 고유명·수치 없이 설명 가능함.
3. 실패 사례와 적용하지 말아야 할 조건이 있음.
4. 자동 또는 사람 검증 조건이 있음.
5. 프로젝트 코어를 바꾸지 않고 어댑트 가능함.
