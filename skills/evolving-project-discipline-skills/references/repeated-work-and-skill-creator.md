# Repeated Work and Skill Creator

반복 실행·재작업·실패가 관찰되거나 사용자가 재사용화를 요청했을 때만 읽는다. 매 작업마다 새 Skill·보고서를 만들라는 지침이 아니다.

## 작은 재사용 단위 선택

기존 작업 기록에서 입력, 반복된 처리/판단, 실패 사례, 실제 consumer, 재실행 명령을 복원한다. 실제 반복 횟수·시간이 없으면 비용 절감률을 발명하지 않는다.

| 관찰된 차이 | 기본 선택 |
|---|---|
| 같은 판단·검수 절차가 반복 | 기존 Skill의 mode/reference 보강 |
| 동일한 기계적 검사·변환을 재작성 | 기존 스크립트 재사용 또는 테스트 가능한 모듈 추출 |
| 프로젝트별 경로·수치·규격만 다름 | 해당 프로젝트 설정/데이터; 공용 코드에 프로젝트 상수 삽입 금지 |
| 독립 trigger·입출력·검증·승인 경계가 반복됨 | 작은 독립 Skill |
| 일회성·재사용 이익 미확인 | 현행 owner 기록으로 종료; 승격하지 않음 |

예: 여러 프로젝트에서 아이콘 크기·알파 검사를 반복한다면 기존 검사기를 먼저 찾고, 공용 판정과 프로젝트별 규격을 분리한다. 명령 실행은 모듈, 결과 해석·실패 처리만 Skill이 맡는다. 크기 검사를 통과해도 시각 품질/사용자 승인을 통과한 것은 아니다.

## 실제 제작 경로

1. 현재 host의 available skills에서 `skill-creator` 제공 여부를 확인한다. 제공되면 그 실제 `SKILL.md`와 필요한 reference를 읽고 재사용한다. 특정 사용자 절대 경로나 캐시 버전을 공용 규칙에 고정하지 않는다.
2. 승인된 목적, trigger/비사용 조건, 기존 owner, 실제 입력/산출물, consumer, 검증/복구와 보호 범위를 제작 입력으로 준다. 이름만 다른 creator를 Base에 만들지 않는다.
3. 미제공이면 `CREATOR_UNAVAILABLE`로 명시하고 이 Skill의 수동 패키지 작성·등록 경로를 사용한다. 설치/유료 API/외부 plugin을 자동 추가하지 않는다. creator 사용 여부와 패키지 구현 여부를 따로 보고한다.
4. 반복 코드는 실행 가능한 helper로, 상세 제작법은 직접 연결된 조건부 reference로 둔다. 기존 책임 문서를 복제하거나 설명문을 모든 프로젝트에 배포하지 않는다.
5. creator가 제공되면 그 구조 검사를 실행하고, 모든 경로에서 Base의 Registry·coverage·구현 증거·참조 검사를 실행한다. 미제공이면 `CREATOR_UNAVAILABLE`, creator 검사 `NOT_RUN`을 기록하고 수동 작성 패키지를 Base 검사로 검증한다. creator 검사를 통과했다고 주장하지 않는다. 실제 모델 행동, 도구 실행, 프로젝트 Pilot, runtime은 별도 증거다.

## 범위·발견·배포

- 공용 방법은 Base의 `skills/SKILL_REGISTRY.json`과 `START_HERE.md`를 통해 찾는다. Base `skills/` 등록은 모든 앱의 native 자동 설치와 같지 않다.
- 프로젝트 전용 확장은 프로젝트의 현행 skill registry/adapter와 기존 전용 경로가 우선이다. Codex native discovery가 필요한 경우 현재 공식 문서와 실제 host가 인식하는 위치를 확인하고, 프로젝트가 채택한 Base source/pin을 해석하는 얇은 진입점만 사용한다. Base 본문을 수동 복제해 다른 정본으로 만들지 않는다.
- 다른 프로젝트의 version lock·등록·설정·로고·자산은 자동 갱신하지 않는다. 다음 해당 작업의 current-authority/adoption 검사에서 필요한 범위만 연결한다.
- 현재 승인된 재사용화 작업 안의 기술 구현은 이어가되, 발견된 새 공용 정책·새 권한·범위 확대는 기존 intake/승격 승인을 따른다. 반복 발견 자체는 자동 쓰기 권한이 아니다.

## 검증과 학습

정상 요청, 인접하지만 비대상인 요청, 필요한 도구 미제공, 프로젝트별 설정 차이를 확인한다. 기존 명령·문서·소비자가 유지되는지 검사한 뒤 실제 결과와 증거 상한만 기존 Learning Log에 남긴다. 실제 개선이 없으면 `NO_NEW_REUSE_LEARNING`이 정상이다.

공식 참조: [OpenAI Build skills](https://learn.chatgpt.com/docs/build-skills). 2026-09-16 확인: 선택적 로드·내장 creator 재사용을 ADOPT, host별 발견/배포는 프로젝트 규칙에 ADAPT. 설치 위치·도구 기능이 바뀌면 공식 문서와 실제 host를 다시 확인한다.
