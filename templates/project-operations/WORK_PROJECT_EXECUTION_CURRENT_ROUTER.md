> 프로젝트 사실·세부 절차를 복제하지 않고 current owner와 공개 5단계 lifecycle을 연결한다.

과거 대화와 Memory는 discovery 후보일 뿐이다. 충돌하면 `CONTEXT_DRIFT_RECHECK_REQUIRED`다.

## 2. 시작 전 정본 교정

새 production·Codex mutation 전에 `WORK_PROJECT_START_CANON_CHECKLIST.md`로 다음을 확인한다.

```text
핵심 재미 / player promise / core loop
핵심·지원 시스템 / actual consumer
evidence-based SWOT
current stage / active Slice / accepted frontier
구현·test·Visual·Audio 상태
remaining work / dependency·player value·risk work order
stale·duplicate·conflict·missing canon / destination readback
```

승인 범위의 작은 결함은 먼저 고친다. Preflight는 current truth 복원이며 새 핵심 기획 승인이 아니다.

## 3. 공개 5단계 lifecycle

```text
FIVE_STAGE_LIFECYCLE_IS_PUBLIC_WORK_SEQUENCE
EXISTING_WORK_MODES_AND_PROFILES_ARE_INTERNAL_OWNER_MAPPING

1. STAGE_1_PLANNING_WITH_USER
2. STAGE_2_PREPRODUCTION_REVIEW
3. STAGE_3_GAME_INPUT_PRODUCTION
4. STAGE_4_CODEX_IMPLEMENTATION_AND_MACHINE_CLOSEOUT
5. STAGE_5_USER_VERTICAL_SLICE_VALIDATION
```

상세 Gate·packet·재진입·완료 상태는 `WORK_FIVE_STAGE_VERTICAL_SLICE_LIFECYCLE.md`가 소유한다.

- Stage 1: 핵심 재미·시스템·선택·보상·첫인상·차별점을 필요 시 benchmark-informed Grill Me로 사용자와 확정.
- Stage 2: 기획 독립 검수. asset production·Codex 구현과 분리.
- Stage 3: Work-owned Visual·Audio·UI·Data·VFX·권리·QA 입력 완료.
- Stage 4: Codex 단일 구현 + Machine QA + Work final review + build/merge/readback.
- Stage 5: 사용자가 exact build를 검증하고 다음 결정을 내림.

```text
ROUTINE_APPROVAL_DOES_NOT_AUTO_APPROVE_CORE_PLANNING
AUTOMATED_VERTICAL_SLICE_READY != VERTICAL_SLICE_COMPLETE
```

기존 minimum-transition Profile의 Stage A/B/C는 내부 실행 집계이며 공개 stage identity와 완료 판정은 5단계 owner가 우선한다.

## 4. Work↔Codex 최소 전환

```text
Stage 1 planning approved
→ Stage 2 review approved
→ Stage 3 WORK_PRODUCTION_INPUT_PACKET / READY_FOR_SINGLE_CODEX_WINDOW
→ Stage 4 CODEX_SINGLE_IMPLEMENTATION_WINDOW
→ Work final review·canon sync·merge/readback
→ downloadable build / AUTOMATED_VERTICAL_SLICE_READY
→ Stage 5 user validation
```

작은 누락마다 왕복하지 않는다. 실제 구현은 current Codex handoff owner로 전환하고 Work가 구현됐다고 추측하지 않는다.

## 6. Evidence identity

`WORK_EXECUTION_EVIDENCE_IDENTITY_INTEGRITY.md`로 분리한다.

```text
product baseline SHA != documentation/router sync SHA
validation HEAD != build/runtime candidate HEAD
TEST_LOGIC_PASS != CI_GATE_PASS
Godot import cache != product source
LOCAL_VISUAL_CANDIDATE != PROJECT_ASSET_APPROVED != RUNTIME_PROMOTED
local commit != remote synchronized
machine QA != Human usability != Player Experience
```

player-facing bytes/package 설정 변경 시 영향 후보를 supersede하고 필요한 Gate를 다시 수행한다.
