# `[프로젝트명]` Work↔Codex 최소 전환·로컬 Visual 시작 지시문

> `[프로젝트명]`만 실제 이름으로 바꿔 Work 채팅에 붙여넣는다. 이 파일은 기존 Starter를 복제하지 않고 current Base owner와 local-Visual adapter를 활성화하는 얇은 진입문이다.

```text
[프로젝트명] 작업을 재개해.

과거 채팅이나 Memory를 current truth로 사용하지 말고 Base latest completed main과 정확한 Project GitHub·Notion·실제 구현을 fresh-read해.

먼저 다음 current Base 파일을 읽고 순서대로 적용해.

1. templates/project-operations/WORK_CODEX_MINIMUM_TRANSITION_STARTER_PROMPT.md
2. templates/project-operations/WORK_PROJECT_START_CANON_CHECKLIST.md
3. templates/project-operations/WORK_CODEX_MINIMUM_TRANSITION_VERTICAL_SLICE_PROFILE.md
4. templates/project-operations/WORK_PROJECT_LOCAL_VISUAL_ASSET_DELIVERY_PROFILE.md

이 메시지는 현재 승인된 Playable Slice에 대해 routine 권장안·안전한 Git 동기화·프로젝트 범위 Godot/컴퓨터 조작·Work→Codex 최소 전환과 함께 다음 Visual 전달 방식을 명시적으로 승인한다.

PROJECT_LOCAL_VISUAL_BINARY_FIRST
NOTION_VISUAL_STRUCTURE_REFERENCE_ONLY
NO_NOTION_BINARY_UPLOAD_REQUIRED

Notion의 Project Home·Visual Bible·Asset Catalog·Flow·Production 구조와 승인 Art Direction은 계속 참고하고 필요한 human-facing 텍스트·상태는 교정/readback해. 다만 생성 이미지 binary는 Notion을 경유하거나 중복 업로드하지 말고, 실제 callable한 로컬 GPT/file capability로 정확한 프로젝트의 local asset workflow에 저장해.

작업 시작 시 먼저 PROJECT_START_CANON_CHECKLIST로 핵심 재미·핵심 시스템·SWOT·current stage·남은 작업·dependency/player-value 기반 작업순서·Visual 자산 경로를 확인하고 현재 승인 범위의 stale·충돌·누락을 선교정해.

현재 Slice 구현에 사용할 승인 이미지는 local-only 후보로 남기지 말고 project-owned tracked asset과 ASSET_MANIFEST로 승격한 뒤 feature branch commit/push·remote HEAD readback을 완료해 Codex에 project-relative locator와 exact commit으로 전달해.

다른 프로젝트 폴더나 무관한 파일을 조작하지 말고, direct main·force push·admin/ruleset bypass·새 비용·권리 미확인 자산·공개 배포는 금지해. 정말 위험한 항목만 국소 보류하고 독립 작업은 계속해.

Work에서 기획·검수·이미지·사운드·UI·Data·VFX·권리·QA 입력을 모두 준비한 뒤 Codex 단일 구현 window로 전환하고, GUT/Hera 또는 evidence-equivalent machine QA·runtime/build·다운로드 가능한 실행 빌드·안전 병합·post-merge readback까지 현재 Slice의 machine-executable required work를 0으로 만들어.

Human usability와 Player Experience는 사용자가 실제 빌드를 플레이하기 전까지 NOT_RUN으로 유지하고, 사용자 검증 전에는 다음 Slice로 자동 진입하지 마.
```
