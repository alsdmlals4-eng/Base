# `[프로젝트명]` Work↔Codex 5단계 자동 버티컬 슬라이스 시작 지시문

> `[프로젝트명]`만 실제 이름으로 바꿔 Work 채팅에 붙여넣는다. 세부 계약을 복제하지 않고 current Base Router와 exact Project canon을 사용한다.

```text
[프로젝트명] 작업을 재개해.

과거 채팅·Memory를 current truth로 사용하지 말고 Base latest completed main과 exact Project GitHub·Notion·actual implementation을 fresh-read해.

가장 먼저 다음 current router와 공개 lifecycle owner를 읽고 적용해.

templates/project-operations/WORK_PROJECT_EXECUTION_CURRENT_ROUTER.md
templates/project-operations/WORK_FIVE_STAGE_VERTICAL_SLICE_LIFECYCLE.md
THIN_ROUTER_NOT_SECOND_CANON
CURRENT_BASE_OWNER_WINS_ON_DRIFT
```

Router가 current owner를 resolve하며 이 파일의 오래된 문구보다 current Project/Base owner가 우선한다. Router가 현재 연결하는 주요 owner는 다음이며 상세 순서·successor는 Router에서 다시 확인해.

```text
WORK_CODEX_MINIMUM_TRANSITION_STARTER_PROMPT.md
WORK_PROJECT_START_CANON_CHECKLIST.md
WORK_CODEX_MINIMUM_TRANSITION_VERTICAL_SLICE_PROFILE.md
WORK_PROJECT_LOCAL_VISUAL_ASSET_DELIVERY_PROFILE.md
WORK_EXECUTION_EVIDENCE_IDENTITY_INTEGRITY.md
```

```text
1. STAGE_1_PLANNING_WITH_USER · 기획
2. STAGE_2_PREPRODUCTION_REVIEW · 검수
3. STAGE_3_GAME_INPUT_PRODUCTION · 이미지·요소 생성
4. STAGE_4_CODEX_IMPLEMENTATION_AND_MACHINE_CLOSEOUT · 구현(Codex)
5. STAGE_5_USER_VERTICAL_SLICE_VALIDATION · 사용자 검증
```

Stage 1에서는 current canon에 이미 승인된 핵심 결정은 재질문하지 않는다. 그러나 player promise·pointed fun·Core Loop·핵심 시스템·meaningful choice·보상/실패·첫인상·차별점·판매 포인트·주요 UX/경제/서사/Art Direction/Slice 범위가 없거나 충돌하면, fresh 벤치마킹·성공/실패 사례·최소 3개 실질 대안을 준비한 뒤 Grill Me로 사용자와 한 결정씩 확정해.

```text
CORE_PRODUCT_DECISIONS_REQUIRE_GRILL_ME_WHEN_UNRESOLVED
ROUTINE_APPROVAL_DOES_NOT_AUTO_APPROVE_CORE_PLANNING
DELEGATED_RECOMMENDED_DEFAULT_APPROVAL
NO_ROUTINE_APPROVAL_STOPS
HIGH_RISK_DECISIONS_DEFER_AND_BUNDLE
```

새 production·Codex mutation 전에 `PROJECT_START_CANON_CHECKLIST`로 핵심 재미·핵심/지원 시스템·SWOT·current stage·actual implementation/test/Visual/Audio·remaining work·dependency/player-value work order를 확인하고 stale/conflict/missing canon을 선교정·readback해.

Stage 2에서는 Stage 1 기획을 실제 정본·구현·Reuse·benchmark·scope·system/data/UI/Flow·Visual/Audio/VFX consumer·rights·accessibility·platform·acceptance/test/build 관점에서 독립 검수해. 제품 의미 finding은 Stage 1로, 입력 requirement는 Stage 3으로 보내며 검수 중 asset production이나 Codex 구현을 섞지 마.

Stage 3에서는 Work가 current Slice의 기획·UI/UX·Data·Visual·Audio·VFX·copy·localization·권리·Acceptance·QA 입력을 모두 준비하고 `WORK_PRODUCTION_INPUT_PACKET = READY_FOR_SINGLE_CODEX_WINDOW`까지 닫아.

```text
PROJECT_LOCAL_VISUAL_BINARY_FIRST
NOTION_VISUAL_STRUCTURE_REFERENCE_ONLY
NO_NOTION_BINARY_UPLOAD_REQUIRED
```

Notion의 Home·Visual Bible·Asset Catalog·Flow·Production과 Art Direction은 참고·교정·readback하되, 이미지 binary는 exact project-local workflow에 저장해. 구현에 쓸 승인 자산은 tracked project asset + ASSET_MANIFEST로 승격하고 SHA-256·provenance·rights·commit/push/remote HEAD를 readback해 Codex에 project-relative locator로 전달해.

Stage 4에서 한 번만 Codex로 전환해 actual code·Scene·Resource·runtime wiring·tests·build를 구현해. GUT/Hera 또는 evidence-equivalent Machine QA, Work final evidence review, valid finding 교정, exact-head CI, safe squash merge, post-merge readback, 다운로드 가능한 build와 SHA-256·clean launch smoke까지 닫아.

```text
CODEX_SINGLE_IMPLEMENTATION_WINDOW
AUTO_GIT_FETCH_AND_SAFE_PULL
AUTO_PUSH_CURRENT_TASK_BRANCH_AFTER_VERIFICATION
AUTO_LAUNCH_GODOT_WHEN_CALLABLE
MACHINE_QA_FIRST
IMPLEMENTATION_REALITY_GATE
TEST_LOGIC_PASS != CI_GATE_PASS
USER_DOWNLOADABLE_BUILD_ARTIFACT_REQUIRED
AUTOMATED_VERTICAL_SLICE_READY != VERTICAL_SLICE_COMPLETE
```

Git은 exact remote/upstream/default branch를 발견해 fetch, 안전한 ff-only pull, current-task branch push와 remote readback을 자동 수행해. direct main, force, blind reset/clean/rebase, 다른 open PR takeover, admin/ruleset bypass는 금지해. 지연 시 bounded retry → evidence-equivalent fallback → local defer → independent ready work로 계속해.

Stage 5에서는 사용자가 exact 다운로드 build를 실제 실행해 대표 흐름·조작·가독성·선택·비용/위험·결과·Visual/Audio feedback·실패 이유·보상·감정·기억·차별점을 검증하게 해. finding은 `core/fun→Stage 1`, `comprehension/spec→Stage 2`, `Visual/Audio/input→Stage 3`, `implementation defect→Stage 4`로 되돌려.

```text
ADVERSARIAL_REVIEW_UNTIL_CLEAN
STALL_SIGNAL_ROUTE_SWITCH
SCOPE_BOUNDED_REQUIRED_WORK_ZERO
HUMAN_USABILITY_EVIDENCE: NOT_RUN
PLAYER_EXPERIENCE_EVIDENCE: NOT_RUN
VERTICAL_SLICE_COMPLETE_REQUIRES_USER_VALIDATION
NO_NEXT_SLICE_BEFORE_USER_DECISION_GATE
```

Human usability와 Player Experience는 사용자가 실제 다운로드 빌드를 플레이하기 전까지 NOT_RUN이다. 각 Stage의 machine-executable required work를 0으로 만든 뒤 actual-state rescan과 최소 5회 full-scope 적대적 검토에서 blocker 0을 확인해. 사용자 실제 검증과 canonical reflection/readback 전에는 `VERTICAL_SLICE_COMPLETE` 또는 다음 Slice 진입을 주장하지 마.

중요 결정은 Existing Solution First와 ADOPT / ADAPT / REJECT로 비교하고 trigger가 맞는 Brainstorming/Superpowers·TDD·systematic debugging·verification-before-completion을 실제 실행해. 읽은 Skill과 실행한 Skill을 구분하고, 실제 구현·runtime·artifact·사용자 검증 없이 완료를 주장하지 마.
